# AGENTS.md

Guidance for AI agents and contributors working on `superset-api-plus`, a typed Python client for the
Apache Superset REST API. Read this before changing code.

## Language

**Everything in this repository is in English**: code, identifiers, docstrings, comments, log and
exception messages, tests (names and docstrings), scripts, configuration comments, README, CHANGELOG,
this file and commit messages. The repository is public (GitHub/PyPI). Issue tracking happens in an
institutional GitLab and is written in Portuguese; that does not change the language of this repository.

## Target and sources of truth

- Target Superset version: **6.1.0** (Flask-AppBuilder 5). Python **>= 3.10**, tested on 3.10 and 3.14.
- **Accepted request fields** come from the official OpenAPI specification
  (`components.schemas.{Resource}RestApi.post/.put`). The `/_info` endpoint is **not** a source of
  accepted fields: in 6.1.0 `ChartRestApi` reports `add_columns = edit_columns = ["slice_name"]` while
  validating bodies with `ChartPostSchema`/`ChartPutSchema`. Each REST model declares `POST_FIELDS` and
  `PUT_FIELDS`; `add()`/`save()` use them.
- **Allowed values** come from the Superset **source code**, not from the specification: many fields
  typed as `string` in the spec are enums in the backend (`superset/utils/core.py`, `constants.py`,
  `common/chart_data.py`) or `choices` in frontend control panels (`controlPanel.tsx`) and
  `src/explore/constants.ts`. Model them as enums with the official values and cite the source.
- **Rule for every `str` attribute**: whenever a model attribute is (or would be) typed as `str`,
  inspect the Superset source code of the target version to check whether it is an enum or a closed set
  of `choices`. If it is, type it with an enum holding the official values (add the source to
  `bin/scripts/extract_superset_enums.py` and the enum to `tests/unit/test_enum_conformance.py`); keep
  `str` only for genuinely free text (titles, SQL, labels, names of the instance's objects) and declare it
  with the reason in `tests/unit/test_attribute_types.py`. The `model-attributes` hook rejects an enum
  without a declared source and a `str` field that is neither an enum nor declared free text.
- **Query building**: in the Superset UI the `query_context` is derived from `params` by each plugin's
  `buildQuery`. `supersetapiplus/charts/build_query.py` is a port of that code (checked against the
  frontend captures); charts built in code send its result, charts read from Superset keep their stored
  `query_context` unless `chart.derive_query_context()` is called.
- Versioned excerpts of the Superset sources live in `tests/fixtures/` and are **generated by scripts**,
  never edited by hand:
  - `bin/scripts/extract_openapi.py <version>` → `superset_openapi_<version>.json`
  - `bin/scripts/extract_superset_enums.py <version>` → `superset_enums_<version>.json`
  - `bin/scripts/extract_ui_references.py <version>` → `ui_references_<version>/` (needs the test
    stack with `SUPERSET_LOAD_EXAMPLES=1`)
  - `bin/scripts/extract_query_contexts.py <version>` → `ui_query_contexts_<version>/`: the `form_data`
    and `queries` the frontend sends to `/api/v1/chart/data` when each reference chart opens in Explore
    (same stack, plus Playwright with Chromium; `CHROME_PATH` selects the browser)
  - `bin/scripts/extract_ui_defaults.py <version>` → `ui_defaults_<version>/`: the form_data Explore posts
    for a new chart of each supported viz_type (controlPanel defaults); a chart created in code gets the
    same params (`tests/unit/test_ui_defaults.py`, in the `model-attributes` hook)
  To support a new Superset version: regenerate the excerpts, run the tests, fix the divergences.

## Behavioral rules of the library

- **Lossless round trip**: reading an object from the API and writing it back must not lose or add
  data. Unmodeled keys are preserved (`PRESERVE_EXTRA_FIELDS`); keys absent in the input stay absent
  (`MissingField`), e.g. no `"groupby": []` or `"metrics": []` added on re-serialization; JSON fields
  that are null are written as `null`, not as the text `"null"`.
  Objects read from Superset skip the checks meant for objects built in code (non-empty `orderby` or
  `metrics` in a query, `params` keys present in `query_context.form_data`): what Superset stored is
  written back as read. Diverging values between `params` and `form_data` are still rejected.
- **Authentication**: instances where the `Public` role has permissions ignore JWT on public endpoints
  (FAB 5). Use `client.enable_session_mode()` (login form cookie + `X-CSRFToken`/`Referer`). In JWT mode
  a rejected token renews it once with the refresh token: a 401, or the 422 `{"msg": ...}` that
  flask-jwt-extended returns for a malformed token (both raise `UnauthorizedError` with the server `msg`).
- **HTTP**: retries transient failures only on idempotent methods (never POST), except 429 (rate limit:
  the request was not processed, so any method is retried, honoring Retry-After); HTTP errors map by
  status to `UnauthorizedError`/`ForbiddenError`/`ResourceNotFoundError`/`UnprocessableEntityError`
  whatever the body format (`message`, or the SIP-40 list in `errors`); other statuses with an error list
  raise `ComplexBadRequestError`; all are subclasses of `BadRequestError`. TLS is verified by default.
- **Security**: never log secrets (use `supersetapiplus.utils.sensitive` masking); never commit
  credentials (`.pypirc` and `.env` are ignored); never put institutional data in the repository —
  tests use synthetic payloads or Superset public examples only.
- **No hardcoded configuration**: network parameters come from `SUPERSET_API_PLUS_*` environment
  variables (timeouts, retries, backoff); the test stack is configured through `.env`
  (template: `.env.example`); examples read `SUPERSET_URL`, `SUPERSET_USERNAME`, `SUPERSET_PASSWORD`.
- **Public API stability**: renames keep the old name as an alias emitting `DeprecationWarning`. The
  following API is used by an external integration and must keep its import path and signature:
  `SupersetClient(url, user, password, verify=...).enable_session_mode()`,
  `client.datasets.find_one(QueryStringFilter)`, `client.charts.find_one(..., full=True)`,
  `client.charts.add(chart)`, `chart.save()`, `Chart.get_class(viz_type, module)`,
  `supersetapiplus.charts.charts.Chart`, `supersetapiplus.query_string.{QueryStringFilter, QueryOperator}`,
  `supersetapiplus.exceptions.NotFound`, `client.dashboards.attach_charts(dashboard)`,
  `dashboard.reset_layout()`, the `position_json` builder (`add_tabs`, `add_tab`, `add_row`, `add_markdown`,
  `add_divider`, `add_chart`), `supersetapiplus.dashboards.layout.ChartRef` and the `json_metadata` native
  filter methods (`clear_native_filters`, `add_filter_divider`, `add_native_filter`).
- **Dashboard layout** (`dashboards/layout.py`): `position_json` is kept as the flat component map Superset
  stores, so a read-and-save is lossless. Top-level tabs live inside the grid (`ROOT → GRID → TABS`), as
  in dashboards exported by Superset. Native filter scopes (`chartsInScope`/`tabsInScope`) are computed
  only for items created by the library; items loaded from Superset are written back untouched.
- **Chart ↔ dashboard association** is done with `Charts.add_to_dashboard` / `Dashboards.attach_charts`
  (PUT of `dashboards` on the chart); `chart.save()` does not send `dashboards`.

## Quality gates

- `pre-commit install` once per clone. Hooks: ruff, codespell, LF line endings (`.gitattributes` also
  enforces LF), `complexity-ratchet` (ruff C901, limit 10: new or worsened functions above the limit are
  rejected; legacy functions may be edited without increasing their complexity), `superset-conformance`
  (request payloads and routes vs. the OpenAPI specification) and `model-attributes` (enums and `str`
  fields vs. the Superset source). `mypy` runs on demand
  (`pre-commit run mypy --hook-stage manual`) until the code passes `mypy --strict`.
- CI (`.github/workflows/python-package.yaml`): tests on Python 3.10–3.14 on push/PR; pre-commit on
  the PR diff. CI/CD changes require explicit authorization from the maintainer.
- Every bug fix comes with a test that fails before the fix. Prefer tests of the public contract
  (results observed on the server) over implementation details.
- **Server behavior is tested against the real Superset**, in `tests/integration` (one module per area:
  auth, errors, charts, dashboards, data, sql, assets). HTTP mocks are a guess about the server: a mocked test passed
  while the real 6.1.0 rejected the request. `tests/unit` mocks HTTP only when the real server cannot
  produce the condition deterministically (5xx and retry, asynchronous SQL Lab, TLS on the plain-HTTP
  stack) or to run offline in a hook (OpenAPI conformance), and the module docstring says why. Pure
  logic (serialization, layout, buildQuery, enums) stays in `tests/unit` without HTTP.
- Integration tests: `docker compose -p superset-api-plus up -d --build`, then
  `SUPERSET_INTEGRATION=1 pytest tests/integration`, then `docker compose -p superset-api-plus down -v`.
  They create and remove their own objects (prefix `zz-superset-api-plus-test`; the `cleanup` fixture
  removes them even when a test fails). Tests that create users
  (`only_test_stack`) are skipped when `SUPERSET_URL` points to another instance. The Docker host may be
  shared with other projects: only manage this compose project; never run `docker system/image/volume
  prune`.

## Workflow

- Plans become an issue (parent) with one task per implementation item in the institutional GitLab.
- One commit per task (or coherent part of it), in English (Conventional Commits). The message ends
  with one line per related institutional issue: `issue #NNN -- gitlab institucional`, plus the
  co-author line when an agent wrote it. After pushing, comment on the GitLab issue with the GitHub
  commit link.
- Do not rewrite pushed history or force-push without explicit confirmation from the maintainer.
- Avoid `git stash` in a shared working tree; compare against `HEAD` with `git archive HEAD | tar -x`
  into a scratch directory.
- Structural changes (module moves, renames) must be justified by a concrete finding and keep
  backward-compatible aliases.

## Roadmap decisions already taken

- Models will move to **pydantic v2** during the package reorganization: `extra="allow"` for free-form
  Superset structures, discriminated union by `viz_type`, `from_json`/`to_dict`/`to_json`/`validate`
  kept as a facade. Public API fully typed (`mypy --strict`).
- Package layout target: `core/` (serialization), `transport/` and `auth/` (HTTP), `resources/`
  (one subpackage per REST resource), `charts/`, `dashboards/` (`layout/`, `native_filters`),
  `services/` (cross-resource operations); layer contracts checked with `import-linter`.
- Dependency management will migrate to **uv** (`pyproject.toml` as the single source, `uv.lock`,
  dependency groups). Runtime dependency floors must stay at or below the constraints of the Airflow
  version used by the integration that embeds this library, and the suite must pass with the lowest
  direct versions.
