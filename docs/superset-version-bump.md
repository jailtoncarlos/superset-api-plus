# Supporting a new Superset version

Checklist for moving the target version (today 6.1.0, see AGENTS.md) to a newer Superset. The library keeps
checked excerpts of the Superset sources instead of importing Superset; every step below regenerates or
re-checks one of them. `<v>` is the new version tag.

## 0. Start from the drift report

The scheduled workflow `.github/workflows/superset-drift.yaml` (Mondays, or run by hand with other refs)
runs `bin/scripts/superset_drift.py`: the offline extractors (OpenAPI subset, enums, example layouts) on the
newest Superset release and on master, compared with the pinned excerpts without provenance and version
stamps. It fails when the newest release differs (a new release to support, or a fixture edited by hand);
master is reported only. The job summary lists each difference by path (`+` added, `-` removed, `~`
changed) and an extraction that fails names the symbol that disappeared. Locally:

```bash
python bin/scripts/superset_drift.py --fail-on latest master <v>
```

The excerpts captured from the UI (`ui_*`, query contexts) need the stack on the new version and are not
part of the report.

## 1. Regenerate the excerpts

All of them are generated by scripts, never edited by hand (`tests/fixtures/`):

```bash
python bin/scripts/extract_openapi.py <v>         > tests/fixtures/superset_openapi_<v>.json
python bin/scripts/extract_superset_enums.py <v>  > tests/fixtures/superset_enums_<v>.json
python bin/scripts/extract_example_layouts.py <v> > tests/fixtures/example_layouts_<v>.json
```

With the test stack on the new version (`docker compose -p superset-api-plus up -d --build`,
`SUPERSET_LOAD_EXAMPLES=1`, and Playwright with Chromium for the last two):

```bash
python bin/scripts/extract_ui_references.py <v>    # ui_references_<v>/
python bin/scripts/extract_query_contexts.py <v>   # ui_query_contexts_<v>/ (Explore's chart/data requests)
python bin/scripts/extract_ui_defaults.py <v>      # ui_defaults_<v>/ (form_data of a new chart)
```

Point the tests at the new files (the version appears in the fixture names the tests load) and diff each
excerpt against the previous version: every difference is a decision.

## 2. Run the gates and fix the divergences

- `pre-commit run --all-files` (OpenAPI conformance, enums and `str` fields, UI defaults, layers, mypy);
- `pytest tests/unit` and, on the stack, `SUPERSET_INTEGRATION=1 pytest tests/integration`;
- the probe of the dashboard exports of the integration that embeds the library.

## 3. Review what the excerpts cannot decide

- **Request fields**: new or removed properties of `{Resource}RestApi.post/.put` change `POST_FIELDS` /
  `PUT_FIELDS` of the models (the OpenAPI conformance test lists them).
- **Enums**: new values in the backend enums and frontend `choices` (the conformance test fails on each); a
  new `str` model field needs the rule of AGENTS.md (enum or declared free text).
- **Aggregates**: the master branch after 6.1.0 adds `STDDEV_SAMP`, `VAR_SAMP`, `MEDIAN` and `PERCENTILE`
  to the simple metric aggregates and the pivot aggregate `"Metric"`; add them to `MetricType` and the pivot
  enums when the new version ships them.
- **Viz types**: new plugins (`VizType`) and new entries of `migrated_viz_types` (legacy types removed and
  migrated): update `REMOVED_VIZ_TYPES` and, for the plugins the library models, `BUILD_QUERY` in
  `charts/build_query.py` against the captured query contexts.
- **Saved query context**: `test_chart_saved_without_query_context_has_no_data_endpoint_in_6_1` pins that
  6.1.0 has no chart data for a chart saved without `query_context`. Newer versions rebuild the query on
  the server (`superset.common.form_data_query_context`); when the test fails, decide whether charts built
  in code still send `derive_query_context()` (thumbnails also used the saved query context; the test stack
  runs without the `THUMBNAILS` feature flag, so check them on an instance that has it).
- **Dashboard layout rules**: `isValidChild.ts` (depths) and `newComponentFactory.ts` (component meta) of the
  frontend, ported in `dashboards/layout/`; the example layouts fixture must still pass without warning.
- **Authentication and errors**: the CSRF and session messages the client renews on
  (`SupersetClient._renew_credentials`) and the SIP-40 body (`SupersetErrorType`, `ErrorLevel`).
- **Flask-AppBuilder**: the filter operators of the pinned FAB version (`fab` section of the enums excerpt).

## 4. Update the target

AGENTS.md (target version), README (supported version), CHANGELOG, the version in the fixture names used by
the tests, the test stack image, and the runtime floors if the integration that embeds the library moved.
