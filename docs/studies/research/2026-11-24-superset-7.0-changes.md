# Apache Superset 6.1.0 → 7.0.0rc3: changes that matter to a REST client

## Scope and sources

- **Compared tags**: `6.1.0` = apache/superset@c83fb2b and `7.0.0rc3` = apache/superset@c872f24
  (2026-11-19). 7.0.0 is still a **release candidate**; the rc3 vote announcement says it "adds about 130
  fixes cherry-picked from master since RC2, with no new features or migrations". The final tag may differ.
- **Flask-AppBuilder**: 5.0.2 → 5.3.0 (apache/superset@c872f24:requirements/base.txt:123;
  apache/superset@c872f24:pyproject.toml:56 asks for `>=5.3.0,<6.0.0`).
- **Read**: `UPDATING.md` section `## 7.0.0` (lines 27–1719) and `CHANGELOG/7.0.0.md` of the rc3 tag; the
  OpenAPI spec of both tags (`docs/static/resources/openapi.json`); backend code (`superset/**/*.py`) and
  the frontend files the library ports (buildQuery, operators, control panels, `MainPreset.ts`); FAB
  `CHANGELOG.rst`, `security/decorators.py` and `security/manager.py` at `v5.0.2` and `v5.3.0`; the PRs
  cited below. This repository's own `bin/scripts/extract_openapi.py` and `extract_superset_enums.py` were
  run against both tags as data readers (the 6.1.0 output equals the committed fixture).
- **Not run**: no 7.0 server was started. Claims whose effect depends on execution are marked
  **[not verified against a running 7.0]**.
- **The published 6.1.0 spec is incomplete.** Several routes and fields that look new when comparing the
  two specs already existed in the 6.1.0 code: `GET /chart/{id_or_uuid}`, `GET /dataset/{id_or_uuid}`, the
  theme API and `theme_id` on dashboards, `uuid` on chart/dashboard/dataset POST (e.g.
  apache/superset@c83fb2b:superset/charts/schemas.py:246), `PUT /dashboard/{pk}/chart_customizations`,
  `validate_expression`, `drill_info`, `export_as_example`, `sqllab/export_streaming` and the FAB groups
  API. Every item below was checked in the **code** of both tags, not only the spec.

## 1. Security model: Subjects

`UPDATING.md` calls it "a breaking API and metadata change" (apache/superset@c872f24:UPDATING.md:1117-1127):

| 6.1.0 | 7.0.0rc3 | Source |
|---|---|---|
| `owners` (user ids) on charts, dashboards, datasets, alerts/reports | `editors` (subject ids); GET returns `editors: [{id, label, secondary_label, img, type}]`; `extra_owners` becomes `extra_editors` | UPDATING.md:1117-1127, 1176-1179; `superset/charts/schemas.py:311-312,375-376`; `superset/dashboards/schemas.py:442-443,505-509`; `superset/datasets/schemas.py:175,203`; `superset/subjects/schemas.py:44-51` |
| Dashboard `roles` behind `DASHBOARD_RBAC` | Dashboard **and chart** `viewers`, behind `ENABLE_VIEWERS` (default `False`); `viewers` sent while the flag is off → 422 | UPDATING.md:110-114, 1125-1126, 1184-1192; `superset/config.py:881` |
| RLS `roles` (required) | RLS `subjects`; required list becomes `[clause, filter_type, name, tables]`; "Regular RLS filters require at least one subject" | UPDATING.md:1127; `superset/row_level_security/schemas.py:39-44,125-204` |
| — | Subject API `security/subject` (read only; `SubjectType` USER=1, ROLE=2, GROUP=3; searchable by `user_id`, `role_id`, `group_id`, `type`); a subject is created or updated automatically with its role or user; listing honors `EXCLUDE_USERS_FROM_LISTS` | `superset/subjects/api.py:53,59-123`; `superset/subjects/types.py:20`; `superset/subjects/hooks.py:55-81`; UPDATING.md:993-996 |
| FAB groups exist but grant nothing in Superset | Groups become access subjects (editors, viewers, RLS); users carry `groups`; `PUT /security/roles/{role_id}/groups` | UPDATING.md:1139-1148 |

PUT schemas raise on unknown fields (apache/superset@c872f24:superset/utils/schema.py:93-95), so a 6.1
body with `owners` or `roles` is rejected with 400 by 7.0 (from the schema code; **[not verified against a
running 7.0]**).

**API keys** (FAB 5.2.0, "add API key authentication support (#2431)"): `Authorization: Bearer <key>` with a
prefix from `FAB_API_KEY_PREFIXES` (default `sst_`); rc3 ships `FAB_API_KEY_ENABLED = False`
(apache/superset@c872f24:superset/config.py:703,2133-2134) and per-resource scopes such as `chart:read`,
`dashboard:write` (`superset/security/api_key_scopes.py`; apache/superset#37973). In FAB 5.3.0 `protect()`
checks the key only after `is_item_public`. The key creation route and payload were not checked.

Other FAB changes: 5.1.0 SAML; 5.2.2 "enforce API login provider validation" (#2462) and "return 403 on
authorization failures"; 5.2.3 distinguishes authentication from authorization redirects (#2479); 5.3.0
dynamic group/role mapping (Flask-AppBuilder `CHANGELOG.rst`, v5.3.0).

## 2. REST API

### Paths

The spec grows from 177 paths (6.1.0) to 230 (rc3). Removed:

| Removed path | Note |
|---|---|
| `/api/v1/async_event/` | GAQ moved to the Global Task Framework (UPDATING.md:513-516) |
| `/api/v1/chart/data/{cache_key}` | same |
| `/api/v1/database/{pk}/ssh_tunnel/` | `ssh_tunnel` still accepted in the database body |
| `/api/v1/dataset/{pk}/related_objects` | now `/api/v1/dataset/{id_or_uuid}/related_objects` |
| `/api/{version}/_openapi` | Swagger off by default (UPDATING.md:1270-1272) |

Added, by area (only those new in the **code**, see "Scope"; the full list is in the appendix):

| Area | Paths | Source |
|---|---|---|
| Soft delete | `POST /{chart,dashboard,dataset}/{uuid}/restore`, `/purge`; `GET /dataset/{uuid}/purge-impact` | UPDATING.md:677-689, 841-867, 1398-1418, 1600-1674 |
| Version history | `GET /{chart,dashboard,dataset}/{uuid}/versions/`, `.../versions/{version_uuid}/`, `POST .../restore`, `GET .../activity/` | UPDATING.md:869-899, 1363-1396; apache/superset#41176, #42469 |
| Security | `security/subject/`, `PUT security/roles/{role_id}/groups`, `DELETE security/users/{pk}/sessions` (`security/groups/` and `security/user_registrations/` were already served by 6.1) | §1; rc3 `superset/security/manager.py:556` |
| Headless query | `GET /datasource/`, `GET /datasource/{type}/{id}`, `POST .../compatible`, `POST .../query` (JSON or Arrow) | apache/superset#43527; `superset/datasource/api.py:459-905` |
| Dashboards | `POST /dashboard/{pk}/export_xlsx/` (async, S3 and e-mail) | CHANGELOG/7.0.0.md |
| Charts | `GET /chart/{pk}/deck_layers/` | CHANGELOG/7.0.0.md |
| Reports | `POST /report/{pk}/execute`, `POST /report/subscribe` | CHANGELOG/7.0.0.md |
| Themes | `GET /theme/system` (rest of the theme API already in 6.1 code) | — |
| Datasets | `GET /dataset/related_objects/` (batch) | CHANGELOG/7.0.0.md |

Every route this library calls is still present in rc3 (login, refresh, `csrf_token`, roles and
permissions, dashboard charts/copy, dataset duplicate/get_or_create/refresh, database test_connection,
assets import/export, chart data, RLS, CSS templates, saved queries, `sqllab/execute`, import/export,
`_info`).

| Schema | Removed | Added |

| `ChartRestApi.put` | `owners` | `editors`, `viewers`, `normalization_changes`, `uuid`¹ |
| `DashboardRestApi.post/put` | `owners`, `roles` | `editors`, `viewers`, `description`, `theme_id`¹, `uuid`¹ |

| `RLSRestApi.post/put` | `roles` | `subjects` |
| `SavedQueryRestApi.post/put` | — | `db_id` lost `type: integer` (documentation only) |

¹ Already accepted by the 6.1.0 code but missing from the published 6.1.0 spec. What is new in 7.0 is that
the chart, dashboard and dataset POST **responses** return the created `uuid` (apache/superset#37806).

Other schema behavior:

- `is_managed_externally` is accepted and discarded on PUT; a PUT (including `PUT /dataset/<pk>/refresh`)
  or a version restore on an externally managed entity returns 403 (`superset/utils/schema.py:88-109`;
  UPDATING.md:497-499, 693).
- Dashboard `css` is validated (rejects `expression(`, script schemes, `@import`, `url(javascript:...)`) on
  POST, copy, import and PUT; `external_url` of charts and dashboards must be `http`/`https` with a host
  (`superset/dashboards/schemas.py:132-178`; `superset/utils/schema.py:59-85`).
- Saving a dashboard layout or copying a dashboard returns 422 when it adds a chart the user cannot read;
  copying requires access to each native filter target (UPDATING.md:100-123).
- `json_metadata` gains `expand_all_slices` and `async_mode` (`DashboardJSONMetadataSchema`).
- Chart data: `/chart/data` is asynchronous only with `async_mode=true` per request (default `false`);
  responses add `warning` (truncated result), `timing`, `queried_dttm`, `detected_currency`
  (UPDATING.md:544-550; `superset/charts/schemas.py:1711-1721,1809,1878,1897-1911`).
- `GET /chart/{pk}/data/?filters_dashboard_id=N` applies the static defaults of the dashboard's native
  filters in scope and returns `dashboard_filters` with a status per filter (apache/superset#38638;
  `superset/charts/data/api.py:105-215`).
- Dashboard import accepts `overwrite_all` (default `false`), which also overwrites related charts,
  datasets and databases (UPDATING.md:1343-1347).
- Dataset column refresh keeps column ids and does not reset `is_dimension`/`filterable`
  (UPDATING.md:132-137, 1369).
- Exports add a `tags` key and `tags.yaml` (UPDATING.md:458-462); dashboard export ids become
  deterministic (apache/superset#36339).
- `GET /version` still returns `version_string` to every user; only SHA and build number become admin-only
  (UPDATING.md:1274-1276; `superset/views/health.py`).

## 3. Charts

### explore_json removal and legacy plugins

apache/superset#41714 removes the `explore_json` pipeline at its declared 5.0.0 EOL: `/superset/explore_json/`,
`/superset/explore_json/data/<cache_key>`, `superset/viz.py` and `Slice.viz` are gone; `useLegacyApi` is
removed from `ChartMetadata`; first-party `legacy-plugin-chart-*` packages are renamed `plugin-chart-*`
and moved to `/api/v1/chart/data`, keeping their `viz_type`; the `can_explore_json` permission disappears
(UPDATING.md:1204-1207). Charts migrated in place keep a NULL `query_context` until opened in Explore or
re-saved (UPDATING.md:1206).

`cal_heatmap` now has a buildQuery (`plugins/plugin-chart-calendar/src/index.ts:52`,
`src/buildQuery.ts:38-53`): `is_timeseries: true` and `extras.time_grain_sqla` derived from
`subdomain_granularity` (min → `PT1M`, hour, day, week, month; default minute). The `viz_type` and the
`domain_granularity`/`subdomain_granularity` choices are unchanged (`src/controlPanel.ts:43-70`;
`MainPreset.ts:115`). The old control panel path under `legacy-plugin-chart-calendar` no longer exists.

All 19 viz types the library models are still in `VizType` and registered (`MainPreset.ts:109-196`).

### pivot_table_v2

The per-table "Aggregation function" control (`aggregateFunction`) is removed; a new "Show values as"
control (`showValuesAs`) and `series_limit` appear; a migration derives `showValuesAs` from the old "Sum as
Fraction of ..." values (UPDATING.md:1303-1331; `plugin-chart-pivot-table/src/plugin/controlPanel.tsx:126,257`).
buildQuery orders columns rows + columns (respecting `transposePivot`) and sends `grouping_sets` when a
metric is not additive, so totals are computed in the database (`src/plugin/buildQuery.ts:66-118`). The 6.1
query schema ignores unknown keys (apache/superset@c83fb2b:superset/charts/schemas.py:1167-1169).

## 4. Soft delete, versions and restore

- `SOFT_DELETE` is `True` by default (apache/superset@c872f24:superset/config.py:715; absent in 6.1.0):
  DELETE archives charts, dashboards and datasets; purge happens after 30 days of retention
  (UPDATING.md:841-866).
- Deleting a database is blocked by its soft-deleted datasets (UPDATING.md:1612).
- Creating a dataset on a table whose dataset is archived is refused: `get_or_create_dataset` returns a 422
  naming the hidden twin; create/duplicate give the generic "already exists" (UPDATING.md:1624).
- Importing a YAML whose UUID is archived restores and updates the object even without `overwrite`
  (UPDATING.md:1626, 1648, 1674). On SQLite metadata the slug of an archived dashboard stays reserved
  (UPDATING.md:1670).
- Purging a dataset requires a `confirmed_impact_token` from `purge-impact` (UPDATING.md:677-689); rison
  filters `*_deleted_state` list archived objects.
- Version history is on by default: PUT returns `old_version_uuid`, `new_version_uuid` and an `ETag`
  (UPDATING.md:888-890); no `If-Match` is required (`superset/charts/api.py` only emits the ETag). The
  version endpoints require being an editor and return 403 for externally managed objects.

## 5. Authentication and errors

- **JWT in `request_loader`**: in 6.1.0 `request_loader` only handled guest tokens
  (apache/superset@c83fb2b:superset/security/manager.py:480-486). In rc3 it also handles
  `Authorization: Bearer`: `verify_jwt_in_request()`, `load_user(get_jwt_identity())`, sets `g.user`
  (apache/superset@c872f24:superset/security/manager.py:2349-2358). apache/superset#39946 fixes
  apache/superset#39834 (with JWT, `GET /database/` and `GET /dataset/` returned `count: 0` even for Admin).
  FAB 5.3.0 `protect()` still runs public items without checking the JWT, so on public endpoints the user
  now comes from this loader. **[not verified against a running 7.0]**
- **CSRF**: for JSON requests a CSRF failure becomes a SIP-40 error `error_type = CSRF_ERROR`, message
  `ex.description` or "The CSRF token could not be validated."
  (apache/superset@c872f24:superset/views/error_handling.py:257-275); 6.1.0 answered through
  `show_http_exception` with a generic type (apache/superset@c83fb2b:superset/views/error_handling.py:147-155).
  Flask-WTF 1.2.2 → 1.3.0 messages still contain "CSRF".
- Unchanged: form login (`route_base = "/login"`, `superset/views/auth.py:34`; `csrf_token` input in
  `templates/superset/spa.html:134-136`), `/security/login`, `/security/refresh`, `/security/csrf_token/`,
  flask-jwt-extended 4.7.1.
- `ALREADY_EXISTS` import message unchanged (`superset/commands/importers/v1/__init__.py:166-171`).

## 6. Dependency bumps (server)

From apache/superset@c872f24:requirements/base.txt: Flask 2.3.3 → 3.1.3, marshmallow 3.26.2 → 4.3.1,
SQLAlchemy 2.0, redis-py 8, pyjwt 2.13.0, Flask-AppBuilder 5.0.2 → 5.3.0; flask-jwt-extended,

default Docker image ships database drivers (psycopg2, mysqlclient) and Chromium; the minimal image is
`-lean` (UPDATING.md:356-377). Validation message texts may change with marshmallow 4
**[not verified against a running 7.0]**.

## 7. Changes irrelevant to an API client (grouped)

- **Server security and operations**: password complexity policy (UPDATING.md:1452-1463); sessions ended
  on account deactivation; `PUT /api/v1/me/`; guest token revocation and stricter guest RLS; AES-GCM
  encryption; SSH tunnel host key check; mandatory TLS for MySQL/Doris; SMTP certificate validation;
  blocked internal hosts in webhooks; larger SQL Lab deny list (UPDATING.md:1231-1240);
  `SQL_MAX_PARSE_LENGTH`; granular export controls; extension supply-chain controls.
- **Infrastructure**: GAQ on the Global Task Framework with websocket tickets; Selenium removed
  (Playwright); Helm labels; Celery tasks for version retention and purge; MySQL READ COMMITTED.
- **Routes without `/superset/` prefix**: only the `Superset`, `ExplorePermalinkView` and tag views move,
  with a 308 redirect (UPDATING.md:1215-1219); `Dashboard.url` without prefix and `thumbnail_url` dropped
  from listings (UPDATING.md:1217, 1333-1341).
- **Alerts and reports**: retry, `include_cta`, XLSX attachments, Slack v2 by default.
- **UI**: mobile mode, Ant Design 6, locale currency symbols, duration formatter, "Select all" in the Value
  filter (UI only, UPDATING.md:707-709), MapLibre/OSM for deck.gl, URL filters in Rison (#39795), tagging on
  by default.
- **Semantic layer and MCP**: semantic layers/views behind `SEMANTIC_LAYERS`; many new MCP tools (a parallel
  integration, not REST).
- **Dataset extras**: `datetime_format` on column PUT, column/metric certification on GET (#43633),
  `rls_filters`/`restricted_count` in related objects, metric/column `uuid` in exports (#42393), export/import
  hooks (#43763), schema-less databases (#39433), array column filters (#41279).
- **Layout robustness**: no 500 on an inconsistent `position_json` (#43575); self-nested components
  prevented or repaired (#44303). Nothing about stale `parents`.
